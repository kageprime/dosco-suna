# Record a delegated token's MFA level when it is minted, from the session that passed the second factor; never infer it from the kind of token

**Rule:** When a credential acts as a person (an OAuth token, a gate-minted token, a delegated session), decide how `mfaGateBlocks` (`apps/api/src/iam/authorize.ts`) judges it and test it in an account with `mfa_required`. Give it a second factor only by recording one at mint time, copied from a browser session that passed it (`oauth_access_tokens.mfa_aal`, the App cookie's `aal`). Bound it: a renewal of whatever carries it drops it, so it never outlives the session that proved it. Never infer it from the token's kind or the route that minted it: a cookie can predate the MFA requirement, and a PAT or an agent session token passes the gate with no second factor. Honor the level in the token's own account only, in `buildActor` (`apps/api/src/middleware/actor.ts`), never request-wide through `c.set('mfaAal')`: account secrets, notifications and the Slack and Teams identity bind read that with no account check.

**Trigger surface:** Minting a token in `apps/api/src/apps/viewer.ts`, `apps/api/src/oauth/`, or any new `kortix_*` credential; changing the App cookie (`apps/api/src/apps/access.ts`), `applyOAuthAccessTokenPrincipal`, `buildActor`, or the MFA gate.

**Incident:** 2026-11-11, prod. A member of a workspace that requires MFA built a static App with `viewer_token_scope: 'api'`. Every call it made as its viewer (`/_kortix/api/v1/*`, the `/_kortix/viewer` token) got `403 account_mfa_required`, although the member had passed MFA to open it: the viewer token is a `kortix_oat_` OAuth token, and OAuth tokens carried no level. Present since gate-minted viewer tokens shipped (8f72fde2d6, 2026-08-27). The first fix (#12419) counted every App viewer token as aal2 in the App's account. A security review (Strix, HIGH) found that a cookie opened before MFA was required renews with no re-check, and that a PAT or an agent session token at the App origin also mints a viewer token: both got aal2 without a second factor. It was reverted from dev (#12421) before any release, and relanded (#12423) with the level recorded at mint time; a second review made a cookie renewal drop the level, so it lasts at most the 8 h of the redeemed cookie. "Sign in with Kortix" tokens still carry no level (parked: `work/oauth-mfa-level/`).

**Enforcement:** REST flow `APP-6` step "in a workspace that requires MFA, an App opened without a second factor does not act as its viewer" (`tests/src/flows/apps.flow.ts`) goes red (`200` instead of `403`) when every viewer token records aal2. `apps/api/src/apps/viewer-session-aal.test.ts` pins that only an aal2 session marks the cookie, that redeem keeps the level, and that renewal drops it. `apps/api/src/__tests__/unit-app-viewer-token-mfa.test.ts` pins the level to the token's own account. `apps/api/src/apps/viewer-token.integration.test.ts` pins the row and the cache.
