# Give every gateway refusal a code, a provider and a fix the person can click, from the gateway to the chat

**Rule:** A failure the person fixes on their own provider account (no key, a key the provider refused, an expired login, a provider account with no funds) carries a gateway `code` and the `provider` in the response body, kortixd maps that code to a `ProviderAuthError` naming the provider, and the chat row offers the fix (Models → that provider). Never let a provider's own refusal fall into a generic bucket: not `UnknownError`, not "temporarily unavailable", and never the Kortix credits card for a provider's "insufficient credits". Every failed `gateway_request_logs` row has an `error_code` and an `error_message`. Check a provider key with one cheap call when it is saved, and record the verdict on the key row; a network failure records `unknown`, never `invalid`, and never blocks the save.

**Trigger surface:** Adding a gateway refusal or a new upstream failure path (`packages/llm-gateway/src/pipeline/simple-handler.ts`, `error-response.ts`, `apps/api/src/llm-gateway/resolution/`), changing how kortixd classifies a turn error (`harness/pi/turn-events.ts` `assistantMessageError`), changing the chat error row (`packages/ui/src/session/status/session-error-banner.tsx`), or changing how a key is saved (Models panel, `kortix providers set`).

**Incident:** A prod audit on 2026-11-11 (14 days, distinct accounts): 41 accounts hit a provider 401 on a key that saved with no check; 45 accounts hit "out of quota", partly because pi asked for `max_tokens` up to the whole context window and OpenRouter refuses a funded key a request it cannot afford; 8 accounts hit Gemini "missing thought_signature" because pi drops Google's `extra_content`; 13 accounts called with a gateway API key whose creator had only a private ChatGPT account and read "Connect Codex"; about 1,700 failed requests (a BYOK 429 or 5xx relayed as received) had no error code or message. kortixd turned every gateway refusal into `UnknownError`, and the chat row had no action. Fixed on branch `provider-key-health`.

**Enforcement:** flow `SEC-POOL-8` (a saved key carries `verification`; a model call on the refused key answers `401` `provider_key_rejected` with `provider`); `packages/llm-gateway/src/pipeline/trace.test.ts` (a failed trace always has a code and a message); `simple-handler.test.ts` (BYOK 401 body, BYOK 429 trace); `dispatch.test.ts` (`BYOK_MAX_OUTPUT_TOKENS`); `http/gemini-thought-signatures.test.ts`; kortixd `pi-turn-error.test.ts` and `pi-model-limits.test.ts`; `@kortix/ui` `provider-key-action.test.ts` and `session-error-banner.test.tsx` (a provider's out-of-credits is not the Kortix credits card).
